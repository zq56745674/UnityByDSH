# 商店 2.0 设计稿（B1）

- **状态**：已实现（2026-10-26，v14 引入；当前存档 v15，技能 2.0 不改商店字段；实现口径见 §11）
- **日期**：2026-10-25（设计） / 2026-10-26（实现回填）
- **关联**：<code>docs/roadmap.md</code> B1、README「终局金币已有硬出口」、<code>docs/rebirth.md</code> §9.4、<code>docs/equipment-reforge.md</code>
- **结论**：推荐做「营地行商」——把商店拆成**战斗内 3 秒补给站**与**局外营地商店**；只卖服务、珍藏与收藏家声望，不卖永久战斗属性。按本稿定价，P1000 期末余额可从 **8.593 亿降到 1.60~1.94 亿**，且不动任何战斗数值。

## 1. 问题

P1000 五槽终局（2026-10-22 复测）打到第 1000 巅峰时：

| 项目 | 数值 |
|---|---|
| 挑战次数 | 119,834 |
| 击杀 | 718,973 |
| 阵亡 | 31 |
| 纯战斗时间 | 5,528.7 min |
| 含刷怪+商店时间 | 17,511.8 min（4× 约 73 小时） |
| 强化累计 | 324,240 金币 |
| 洗练累计 | 708,389 金币 |
| 可计量支出合计 | **1,033,000 金币** |
| 期末余额 | **859,284,167 金币（8.593 亿）** |

这不是「钱不够花」，是**没有可重复的出口**：强化与洗练都是一次性天花板，做完之后金币只剩药水一个出口，而药水在 P1000 几乎不构成支出。

### 1.1 现有出口审计

| 出口 | 价格 / 上限 | 重复性 | P1000 实际支出 |
|---|---|---|---|
| 强化 +0→+15（五件） | 约 5 × 54,000 = 270,000 | 一次性 | 324,240 |
| 洗练到 86% 质量（一套） | 约 1,337,000（0.9 增长口径） | 一次性到目标 | 708,389 |
| 生命药剂 | Lv100 520/瓶，上限 5，商店只开 3 秒 | 经常性，但受喝药频率限制 | **未单独计量** |
| 转生折印记 | 金币项最多 14 枚，印记总上限 110 | 到上限后失效 | 不计入常规支出 |
| 成就 / 首通 / 无尽 | 收入项，不是出口 | — | — |

**必须说清楚的一件事**：P1000 报告只统计强化与洗练，**药水花费没有单独计量**。不要用「119,834 次 × 5 瓶 × 520 = 3.116 亿」当事实——那只是「每次 BOSS 前都补满且每瓶都喝掉」的上界；P1000 角色很难掉到 40% 以下，实际可能远低于此。做定价前应先给探针加一个药水支出计数器，或至少承认这条账是空白。

### 1.2 为什么不能直接加战斗属性

当前平衡基线是「理想五槽 P1000 无尽首死中位 240 层（P10 227 / P90 250）」「P200 终局余额 5,864,020」「新档 30 种子 25 通关」。任何永久攻击/防御/暴伤/掉落/强化上限，都会同时改这三条基线。B1 的第一约束是：**金币出口不能变成战力出口**，否则就是拿经济系统推翻 D2 刚收口的 235~250。

## 2. 目标与非目标

### 2.1 目标

1. 给 P1000 的 8.59 亿一个**可见、可重复、可部分完成**的消耗路径；首版目标不是清零，而是把余额压到 **2 亿以下**。
2. P200 的 586 万也能买到有意义的东西，不能只有 P1000 才配逛。
3. 不使用新货币，不引入随机抽奖，不做每日刷新；单机离线可完整复现。
4. 不动战斗数值、不动强化/洗练上限、不动转生印记折算。
5. 所有购买都是「时间、收藏、外观、声望」，不是「下一层更强」。

### 2.2 非目标（本稿明确不做）

- 金币 → 转生印记（<code>docs/rebirth.md</code> §9.4 已说明会双重折算）。
- 提高强化 +15 上限、提高洗练词条上限、卖「必出传说」。
- 装备赌注 / 开箱 / 随机词条券。
- 战斗内可买的一次性增伤、减伤、复活。
- 每日/每周轮换库存（单机没有可信服务器时钟，且会造成「今天不买就没了」的焦虑）。
- 账号级共享收藏（本作成就、称号、存档都是按槽隔离，商店也应如此）。

## 3. 方案比较

| 方案 | 能吸收多少 | 平衡风险 | 实现成本 | 玩家感知 | 结论 |
|---|---|---|---|---|---|
| **A. 营地行商**（服务 + 珍藏 + 收藏家等级） | 6.6 亿+ | 无（不加战斗属性） | 中 | 中；需要可见的等级/称号 | **推荐** |
| B. 战斗补给站扩展（更多药水/战斗增益） | 受喝药频率限制，且会随难度波动 | 中高（直接改胜率） | 低 | 强 | 只保留现有药水，不扩战斗增益 |
| C. 装备赌注 / 提高强化上限 | 高 | 高（推翻 240 层与 P200） | 中 | 强 | 否决 |
| D. 金币 → 印记 / 金币 → 成就点 | 中 | 高（双重折算 / 成就贬值） | 低 | 强 | 否决 |

选 A 的核心理由：它是唯一**不碰战斗数值**、又能把「8.59 亿」变成「看得见的进度」的方案。B 的问题是药水消耗本身不稳定；C/D 会把经济问题变成平衡问题。

## 4. 推荐方案 A：营地行商

### 4.1 两个商店，不要混在一起

| 表面 | 位置 | 时长 | 卖什么 | 是否改 |
|---|---|---|---|---|
| 战斗内补给站 | 右侧商店卡（<code>GameUI.Build.Right.cs:103-134</code>） | 精英/Boss 前 3 秒 | 生命药剂 | **不改** |
| 营地行商 | 左栏第 5 个顶部徽章（x=154，现有 4 个在 202/250/298/346） | 暂停，无计时 | 服务 / 珍藏 / 收藏家等级 | 新增 |

入口图标复用已有的 <code>ui_shop.png</code> / <code>glyph_shop.png</code>（<code>Assets/Resources/Icons/</code> 里已有），不需要新美术。面板实际为 **840×600 @ (220,60)**，四页签：**服务**、**珍藏**、**声望**、**战绩**（战绩页承载「装备图鉴 / 战斗统计」两项只读服务）。不要试图把 20 件商品塞进 3 秒战斗商店——那是 B1 最容易犯的错。

### 4.2 收藏家等级（主出口）

「收藏家等级」是纯声望：每级只给徽章、头像框颜色、称号与背景色，**不给任何战斗属性**。

- 20 级，价格 <code>cost(n) = 100,000 × 1.5^(n-1)</code>。
- 累计价 <code>sum(n) = 200,000 × (1.5^n - 1)</code>。

| 等级 | 单级价格 | 累计 |
|---:|---:|---:|
| 1 | 100,000 | 100,000 |
| 2 | 150,000 | 250,000 |
| 3 | 225,000 | 475,000 |
| 5 | 506,250 | 1,318,750 |
| 8 | 1,708,594 | 4,925,781 |
| 10 | 3,844,336 | 11,333,008 |
| 15 | 29,192,926 | 87,378,778 |
| 18 | 98,526,125 | 295,378,376 |
| 20 | 221,683,782 | **664,851,348** |

**为什么是 1.5 倍、20 级**：

- 20 级总价 6.6485 亿（逐级取整后实际 **664,851,348**），正好能吸收 P1000 余额的约 77%；买满 20 级后剩 **194,432,819**，已经低于 2 亿目标。
- P200 的 5,864,020 刚好累计到第 8 级（4,925,781），剩 93.8 万；不会出现「中期玩家一分都花不出去」。
- 首级 10 万，高于首次全清 63,800，但只差一次卖装备/一层无尽；它不是新档必须买的东西，作为「第一个长期目标」是合理的。
- 后续若要延长，21 级单级 3.325 亿，曲线不会突然变便宜；不需要重做公式。

每级奖励（不新增战斗数值）：

| 等级 | 奖励 |
|---:|---|
| 1 | 称号前缀「行商」、商店徽章 |
| 5 | 头像框·铜 |
| 10 | 头像框·银 + 背景色调·暖 |
| 15 | 头像框·金 + 伤害数字·金 |
| 20 | 称号「黄金旅人」+ 背景色调·极光 + 商店立绘装饰 |

### 4.3 服务（一次性 QoL）

| 服务 | 价格 | 作用 | 风险 |
|---|---:|---|---|
| 批量强化（+5 / +15） | 150,000 | 一次点到位，仍逐级扣费 | 无战斗数值；只是省点击 |
| 连续洗练（10 连） | 300,000 | 一次洗 10 次，仍逐次扣费与锁词条 | 不提高词条上限 |
| 装备收藏锁 | 200,000 | 标记装备不被自动出售/批量操作 | 纯防误操作 |
| 自动出售规则 | 250,000 | 按品质/评分阈值自动卖 | 只自动化既有手动卖出，不新增掉落 |
| 装备预设 3 套 | 300,000 | 保存/切换 3 套五槽配置 | 只换装，不复制装备 |
| 战斗统计面板 | 200,000 | 显示 DPS 构成、金币/小时、掉落率 | 只读展示 |

合计 **1,400,000**。这些是「买了以后操作更顺」，不是「买了以后更强」。其中自动出售规则需要单独测金币/小时，若超过 5% 收益就调低阈值或取消。

### 4.4 珍藏（外观）

| 商品 | 数量 | 单价 | 小计 |
|---|---:|---:|---:|
| 头像框 | 6 | 0.5M / 1M / 2M / 3M / 5M / 8M | 19.5M |
| 章节背景色调 | 4 | 1M | 4M |
| 伤害数字样式 | 3 | 1.5M | 4.5M |
| UI 强调色主题 | 2 | 2.5M | 5M |
| **合计** | 15 | — | **33M** |

所有外观只改显示，不改任何结算。头像框与称号都按存档槽保存，不跨槽共享。

### 4.5 总吸收与定价验证

| 项目 | 金额 |
|---|---:|
| 收藏家 20 级 | 664,851,348 |
| 服务 6 项 | 1,400,000 |
| 珍藏 15 件 | 33,000,000 |
| **可吸收合计** | **699,251,348** |
| P1000 期末（买满） | 859,284,167 − 699,251,348 = **160,032,819** |
| P1000 只买满收藏家 | 859,284,167 − 664,851,348 = **194,432,819** |
| P200 买 8 级 + 1 项服务 | 5,864,020 − 4,925,781 − 150,000 = **788,239** |

结论：**只买收藏家等级就能把 P1000 压到 2 亿以下**；全部买完是 1.60 亿。P200 不会被迫消费，也不会买不起第一档。

## 7. 验收

### 7.1 纯逻辑

1. 收藏家 20 级价格逐级 1.5 倍；累计价等于 664,851,348（逐级取整口径；设计公式的 346 差异来自取整）。
2. 金币不足时不能买；刚好等于价格时可以买，余额为 0。
3. 重复购买同一服务/珍藏被拒绝；收藏家满级后第 21 次被拒绝。
4. 二次确认：第一次点不扣款，3 秒后失效；第二次点才扣款。
5. 存档 v14 往返：rank / mask / frame / accent 一致；v13 旧档读入 0 / -1。

### 7.2 回归

- <code>BalanceRegression.RunStaticOnly()</code> → PASS。
- <code>AchievementRegression.RunCore()</code> → 644 通过 / 0 失败。
- <code>QuickRegression.RunAllQuick()</code> → 3/3 PASS。
- <code>EndlessPacing</code> 50 种子中位 **242**（P10 230 / P90 252 / max 265），在 D2 的 240 口径容差内（购买不加战斗属性；自动出售只自动化既有手动卖出）。
- <code>NewGameProgression.RunAssert(12345, 30)</code> → PASS。

### 7.3 经济验收

- P1000 买满收藏家后余额 ≤ 2 亿（实际 **194,432,819**）。
- P1000 买满全部后余额约 **160,032,819**。
- P200 能买 8 级收藏家 + 至少 1 项服务，且不出现负金币。
- 首级 10 万在首次全清（63,800）之后一到两次无尽/卖装备可达到；不作为新档硬门槛。

### 7.4 UI

- 1280×720 与 1920×1080 下无文字裁切；四页签不重叠；1M 以上二次确认文案不溢出。
- 未购买/已购买/金币不足/已满级四种状态都有文字，不只靠颜色。

## 8. 风险与开放问题

| 风险 | 说明 | 缓解 |
|---|---|---|
| 纯外观不够有吸引力 | 玩家可能觉得「花 6 亿买称号」空虚 | 收藏家等级给可见徽章/框/背景，且每 5 级有节点；后续可加「行商声望」展示 |
| P200 只能买 8 级 | 中期玩家觉得天花板太远 | 服务与珍藏价格带覆盖 15 万~800 万；P200 可先买服务 |
| 自动出售改经济 | 可能提高金币/小时 | 先测 10 小时金币收入，超过 5% 就收紧阈值 |
| 第 5 个顶部图标拥挤 | 154 与 202 只隔 4px | 1280×720 截图验收；必要时把音乐/商店并成一组 |
| 收藏家等级成为新「必须刷」 | 纯声望不应有最优解压力 | 文案明确「不影响战斗」；不设每日/限时 |
| 存档 v14 迁移 | 旧档字段缺失 | 迁移断言 + v13 手写档测试 + 版本上界测试 |

**开放问题（2026-10-26 已拍板）**：

| 问题 | 决定 |
|---|---|
| 收藏家等级是否按存档槽独立？ | **按槽独立**（与成就/称号一致）。 |
| 自动出售规则是否首版就上？ | **首版就上**；买下后服务页按钮循环「关 → 普通 → 优秀 → 稀有」。 |
| 外观是否允许在战斗内切换？ | **只允许营地内切换**：打开行商面板会冻结战斗；外观本身不改任何战斗数值。 |
| 是否做全槽共享的账号级展示？ | **不做**，避免跨槽重复计数。 |

## 9. 实施顺序（建议）
