# 装备洗练（重铸副词条）设计

状态：2026-10-18 设计并实现并通过验收（原路线图「P1 核心循环 · 步骤 3」）；同日追加**锁词条**（见 §10，§10.9 已实测勾完）
涉及存档：v6（只给 `Equipment` 加字段，缺失即 0，不需要升版本）
相关文件：`GameConfig.cs` / `GameConfigData.cs` / `game_config.json` / `Models.cs` / `LootSystem.cs` / `GameController.cs` / `GameUI.cs` / `GameUI.Panels.cs` / `GameUI.Core.cs`

## 0. 一句话

花金币把一件装备的**副词条整体重抽一遍**：条数不变，种类与数值重来；主属性、武器主词条、品质、强化等级都不动。

它同时解决三个问题：终局金币没有出口、掉落方差无法追赶、装备接近 BiS 之后玩家失去决策。

## 1. 为什么做

### 1.1 终局金币是死钱

`EndgamePacing` 实测（q=20、探针带决策层）：满级时兜里还剩约 **560 万**金币（P200，2026-10-19 带洗练）。
两件装备强化到 +15 一共只花 **24~31 万**，而终局每轮都在卖装备。金币曲线在满级之后是一条只涨不落的直线，玩家看着这个数字没有任何可做的事——这是 README「已知问题」里那条「终局金币没有任何出口」。

### 1.2 装备一旦接近 BiS，掉落系统就不再产生决策

自动换装的口径是「增量期望 DPS + 有效生命/8」。到了终局，能穿上的武器已经是传说 Lv.100~110、倍率 4.0 以上；这时再来一件同品质装备，绝大多数情况评分更低，直接被卖掉。玩家能做的只有「等下一件」——这不算玩法。

### 1.3 副词条是纯运气，而且运气不可追

副词条在掉落时一次性掷定：条数由品质决定（普通 1 / 优秀 1~2 / 稀有 2 / 史诗 3 / 传说 4），种类从 5 种里无重复抽，数值在各自区间里均匀取。
Lv.100 的等级缩放是 ×1.5，于是单条暴击率最高 **12%**、暴击伤害最高 **54%**、攻速最高 **15%**——四条全顶的传说武器和四条全底的传说武器，实际战力差一大截，但玩家只能反复刷、等运气。

洗练把这条运气曲线变成一条**用金币换方差收敛**的曲线：上限不变，只让你逐步逼近它。

## 2. 规则

### 2.1 对象与入口

- 只能洗**当前穿着的**武器 / 衣服（各一张卡），不做背包——本作没有背包，装备只有两个槽。
- 入口在左栏「装备」标题行右侧：原来的「强化」按钮左边再放一个「洗练」，两个按钮并排（x=240 / x=322，宽 76）。
- 打开浮层时整局冻结（与选关 / 技能 / 存档 / 强化同一套规则），并且五个浮层互斥、三选一没选完时拒绝打开。

### 2.2 一次洗练做什么

| 字段 | 洗练后 |
|---|---|
| 副词条**条数** | **不变**（普通 1 条还是 1 条，传说 4 条还是 4 条） |
| 副词条**种类** | 从 5 种池里无重复重抽（与掉落同分布） |
| 副词条**数值** | 每条重新均匀取 `[min, max] × (1 + level × EquipAffixLevelScale)` |
| 主属性（攻击 / 防御 / 生命） | 不变 |
| 武器主词条（暴击率或暴击伤害） | 不变 |
| `qualityMultiplier` / `quality` / `level` | 不变 |
| 强化等级 `enhanceLevel` | 不变 |
| `reforgeCount` | +1（只用于费用递增与展示） |

条数保持不变是硬约束：优秀品质的条数本来是 1~2 随机，如果洗练连条数一起重抽，一件 2 条的优秀装备会被洗成 1 条——花金币反而掉一条词条，没人会接受。所以洗练只重抽「内容」，不重抽「容量」。

### 2.3 随机口径必须与掉落完全一致

种类：从 `EquipAffixNames` 的 0..4 里 Fisher-Yates 洗牌取前 `count` 个，与 `LootSystem.RollAffixes` 同一段逻辑。
数值：`Random.Range(EquipAffixMin[kind], EquipAffixMax[kind]) × levelScale`，与掉落同一公式、同一个 `EquipAffixLevelScale`。

**天花板因此完全不变**：洗练能掷出的最强结果，就是一件掉落的绝对上限；它只降低「你需要等多久才遇到」的方差，不抬高任何一条词条的上限。这是这条系统能安全上线的前提——它不会破坏已经调好的终局 BOSS 强度，只是让有金币的人用时间换确定性。

### 2.4 边界情况

| 情况 | 行为 |
|---|---|
| 该槽位没有装备 | 返回 `NoEquipment`，按钮显示「无装备」并压暗，日志提示「该槽位还没有装备。」 |
| 装备没有任何副词条（理论上不会发生，普通也保底 1 条） | 返回 `NoAffix`，按钮显示「无可洗词条」 |
| 金币不足 | 返回 `NotEnoughGold`，按钮压暗（文案仍是 `洗练 费用`，让玩家看得见还差多少），卡片费用行追加「（不足）」，日志提示「金币不足，无法洗练。」 |
| 锁满了全部词条 | 按钮显示「已全锁」并压暗；`ReforgeEquipment` 返回 `AllLocked`，不扣钱（UI 也拒绝把最后一条未锁的词条锁上） |
| 锁了 n 条 | 只重抽剩下 `AffixCount − n` 条，费用 ×`ReforgeLockFactor^n`（默认 3 → ×3 / ×9 / ×27）；锁住的种类与数值都不动 |
| 洗练后生命上限变小（全属性词条掉了） | `currentHp` 夹到新上限；上限变大时**补差额**，与强化同一套处理，避免「洗练掉血」的观感 |
| 面板打开时正在战斗 | 整局冻结，不推进计时器 |
| 掉落把洗练过的装备换掉 | 旧装备按原价卖出（售价只看等级与品质，不看词条），投资沉没——这是「只洗接近 BiS 的装备」这条决策的成本 |

## 3. 费用

### 3.1 公式

```
ReforgeCost(level, quality, reforgeCount, lockedAffixes)
  = round( (ReforgeBaseCost + ReforgeCostPerLevel × (level − 1))
           × EnhanceQualityFactors[quality]
           × (1 + ReforgeCostGrowth × reforgeCount)
           × ReforgeLockFactor ^ lockedAffixes )   // 默认 3^n，见 §10
```

- 品质系数直接复用强化的 `EnhanceQualityFactors = {0.6, 0.8, 1.0, 1.3, 1.6}`：同样的「品质越贵」直觉，不再造第二套表。
- 初版参数（可热改，写在 `game_config.json`）：

| 参数 | 值 | 含义 |
|---|---|---|
| `ReforgeBaseCost` | 200 | Lv.1 的基础价（未乘品质） |
| `ReforgeCostPerLevel` | 14 | 每高一级加价，Lv.110 的基价 = 200 + 14×109 = 1,726 |
| `ReforgeCostGrowth` | 0.6 | 同一件装备每洗一次，本次费用 +60% |

### 3.2 为什么是线性递增，不是指数

指数（比如 ×1.35/次）到第 15 次就会贵到没人点，等于给系统设了一个隐形次数上限；而这个系统的价值恰恰在「接近上限的最后几口最贵、但确实能吃到」。
线性递增（`1 + 0.6n`）让第 30 次仍是五位数、第 50 次才到十万级，玩家可以按自己的钱包决定停在哪里，没有硬墙。

### 3.3 示例费用

传说装备（品质系数 1.6），第一次 / 第 11 次 / 第 21 次 / 第 31 次：

| 装备等级 | 首次 | 第 11 次 | 第 21 次 | 第 31 次 | 洗 31 次累计 |
|---|---|---|---|---|---|
| Lv.30 | 970 | 6,208 | 11,446 | 16,684 | 30.1 万 |
| Lv.60 | 1,642 | 10,509 | 19,376 | 28,243 | 50.9 万 |
| Lv.100 | 2,538 | 16,243 | 29,948 | 43,653 | 78.7 万 |
| Lv.110 | 2,784 | 17,818 | 32,851 | 47,885 | 86.3 万 |

对照：传说 +14→+15 一级 6,960，整件 +0→+15 累计 54,000。洗练不是「再强化一遍」，它是单件装备的第二次深度投资。

### 3.4 词条质量与收敛速度

定义**词条质量** = 每条副词条的「百分位」（`(值 − min) / (max − min)`，等级缩放会约掉）再取平均，0~100%。

对一件 4 条词条的传说装备做 10 万次蒙特卡洛（每次独立重抽）：

| 目标质量 | 达到所需次数的中位数 | 平均值 | 100 次内达到的比例 |
|---|---|---|---|
| ≥ 65% | 5 | 6.5 | 100% |
| ≥ 70% | 8 | 11.6 | 100% |
| ≥ 75% | 17 | 22.5 | 98.6% |
| ≥ 80% | 31 | 37.0 | 82.1% |
| ≥ 85% | 44 | — | 41.8% |
| ≥ 90% | — | — | 10.1% |

解读：**80% 是一条合理的停手线**——中位数 31 次、按 Lv.110 传说算累计约 86 万金币；再往上每一档都要翻倍的钱，留给「金币真的没处花」的人。

### 3.5 与终局金币总量的关系

终局探针满级时剩约 560 万（P200）。把两件传说都洗到 80% 质量大约吃掉 170 万，洗到 85% 约 340 万——**够花，但不够把两件都洗满**。这正是想要的状态：金币有出口，但出口不封顶；玩家永远有下一个可以花钱的目标，不需要再加第二套货币。

### 4.2 卡片内容

- 第一行：品质色标题（`Equipment.Title`，含 `+15`）。
- 第二行：主属性（`StatLine`，用强化后的值）。
- 三~七行：**每条副词条一行，行本身是按钮**——点一下切换锁定。已锁是 `◆ 已锁`（金）+ 左端 3px 金色竖条，未锁是 `◇ 未锁`（灰）+ 灰竖条；装备上没有的词条行直接隐藏。
- 倒数第二行：`词条质量 72%（4 条）` + `已洗练 6 次`。
- 费用行：`费用 7,614 金币（锁 1 条 ×3）`，买不起时再追加「（不足）」。
- 底部按钮：`洗练 7,614`（买不起时底色 `BtnDisabled`、文字 `BtnDisabledText`）/ `无装备` / `无可洗词条` / `已全锁`。

### 4.3 反馈

日志两条（通道：`AddLog` → `BattleLog.AddSystem`，因为这是系统行为不是战斗行）：

```
◆ 洗练 传说武器 Lv.110 +15  →  花费 7,614 金币（第 7 次，锁 1 条 ×3）
  词条质量 61% → 78%（↑17）    暴击率 +11.6%  暴击伤害 +47.0%  攻击速度 +8.1%  全属性 +6.4%
```

第一条用品质色，第二条用 `LogInfo`；质量变化带 ↑/↓ 与差值。

切换锁定时另记一条 `LogInfo`：

```
锁定 暴击伤害 +47.0% —— 锁 1 条，洗练费用 ×3
```**不做洗练飘字、不做动画**：这是低频决策操作，数字读清楚比演出重要。

### 4.4 刷新分层（不能推翻 #19 的改造）

`RefreshReforgePanel()` 与强化面板同构：面板关着直接 return；刚打开或 `_reforgePanelDirty` 才重写文本。**不做**每帧重算成本/质量——它只会在「打开面板 / 点按钮 / 切存档」时变化。静态刷新计数 `StaticRefreshCount` 不应该因为多了这个面板而上升。

## 5. 与现有系统的交互

### 5.1 评分与自动换装

洗练会改变 `EquipmentScore.Of` 的结果（词条进 DPS / 有效生命），这是预期行为：更强的词条 = 更高的评分 = 更不容易被下一件同主属性的装备换掉。
注意评分只影响「要不要换」，不影响洗练本身；洗练过的装备被打落时仍按等级+品质卖价，**不会**因为词条好而卖得更贵（否则会变成刷金币的套利：洗出好词条再卖掉）。

### 5.2 存档

`Equipment.reforgeCount` 是新增字段，`JsonUtility` 对缺失字段给 0，旧档天然兼容；不升 `CurrentSaveVersion`（v6 语义没变）。
`reforgeCount` 只影响费用与展示，不进评分。

### 5.3 日志频道

系统日志走 `GameController.AddLog`（`BattleLog.AddSystem`）；洗练面板里的错误提示（金币不足 / 无装备）也走这条。战斗行不参与。

### 5.4 探针

`ProbePolicy` 从 2026-10-19 起也模拟洗练：`SpendGoldOnReforge(PlayerData, targetQuality = 0.80f, ...)` 留够药钱后，每次 BOSS 前挑词条质量更低的一件，只洗低于目标质量的那件，锁住已达到目标质量的词条，费用走 `Equipment.ReforgeCostWithLocks`，直到两件都达到 80% 或只剩药钱。它不追 90%：目标定为 80%，因为再往上边际收益明显变慢。
`NewGameProgression` / `EndgamePacing` / `EndlessPacing` 都已调用；`reforgeQuality=0f` 可关掉做 A/B。
新档实测（seed 12345，单关上限 200）：不洗练时 11-10 要 97 次尝试 / 87 阵亡 / P60；默认洗到 80% 后第 11 章只要 20 次 / 10 阵亡、收尾 P44，洗练花费 2,674 金。差距偏大，已写进 README「已知问题」作为待定平衡风险。

### 5.5 平衡风险

洗练上限 = 掉落上限，所以不会突破已经调好的数值区间；但它会**加速玩家到达上限**。
粗算：词条质量 50% → 80%，四条词条的收益大约相当于 +8%~12% 的 DPS 与少量生命，终局 BOSS 胜率会往上抬一点。这属于「可选的终局成长」，方向与用户定的「终局就是要难」不冲突——难的是不洗练也能过、想轻松一点就得掏钱。但 2026-10-19 的 A/B 显示收益比粗算更集中：11-10 的阵亡从 87 次降到 10 次，只花 2,674 金，因此终局墙是否要重新标定待定。

## 8. 本版不做

- **洗练保底 / 下限递增**：那会实质抬高天花板（保底最终把词条推到满值），与「不抬高上限」的前提冲突。
- **结果预览 / 可撤销**：预览会让「看一眼」变成免费信息，撤销则需要保存两份词条状态，都是复杂度换不来体验。
- **洗练过的装备在回收时溢价**：会变成「洗出好词条再卖」的套利。

## 10. 锁词条（2026-10-18 追加）

### 10.1 一句话

洗练前可以锁住若干条词条：**锁住的不重抽**，只重抽没锁的那几条；每多锁一条，本次费用 ×3（×3 / ×9 / ×27）。

### 10.2 为什么加

§2 的洗练是「整体重摇」：想保住一条已经洗到 90% 的词条没有任何办法，只能整件重来。于是方差收敛只剩「次数」一条路，而次数是线性的、花钱是二次的——实测不锁词条追 85% 质量的中位数要 185 次、1310 万金币（§10.6），等于把这条路封死了。

锁词条把「先整体摇到几条好的，锁上，再定向摇剩下的」变成可操作的动作：玩家第一次有了「收敛」而不是「重来」的手段。

### 10.3 规则

| 项目 | 行为 |
|---|---|
| 锁定范围 | 每件装备各自一份锁定状态，最多锁 `AffixCount − 1` 条（全锁 = 没有可洗的词条） |
| 锁住的词条 | 种类与数值都不变，不参与重抽 |
| 未锁的词条 | 条数 = `AffixCount − 锁数`，种类从「未被锁的池」里无重复抽（所以洗出来的词条依然不会和锁住的撞种类），数值公式与掉落完全一致 |
| 条数 / 主属性 / 武器主词条 / 品质 / 强化等级 | 都不变 |
| 费用 | `× ReforgeLockFactor ^ 锁数`，默认 3 → ×3 / ×9 / ×27 |
| 生命周期 | 锁定是**界面上的临时选择**，不进存档；换装（掉落替换）后自动清零，洗练完成后保留（方便连洗） |

### 10.4 费用（默认 `ReforgeLockFactor = 3`）

Lv.100 传说（品质系数 1.6）的单次费用：

| 锁几条 | 倍率 | 首洗 | 第 10 次 | 第 20 次 |
|---|---|---|---|---|
| 0 | ×1 | 2,538 | 16,241 | 31,466 |
| 1 | ×3 | 7,613 | 48,722 | 94,399 |
| 2 | ×9 | 22,838 | 146,166 | 283,196 |
| 3 | ×27 | 68,515 | 438,497 | 849,588 |

### 10.5 为什么是 ×3 指数，而不是线性加价

- 锁 k 条把要摇的方差从 4 条降到 4−k 条：追 80% 质量的中位数次数从 58 → 17 → 5.6 → 2.0，掉了 10~30 倍。线性加价（×1.6 / ×2.2…）会让「锁得越多越划算」，锁词条就成了没有代价的默认操作。
- 指数把每个锁档变成一次明确的承诺：×3 是同一量级、×9 贵一档、×27 是「我要把最后一条磨到顶」。
- 传说 4 条词条最多锁 3 条 → 最高 ×27，不会出现 5 条满锁的 ×81 / ×243 那种失控值（5 条那一档只有未来扩词条池才会摸到）。
- 参数在 `game_config.json` 里（`ReforgeLockFactor`），觉得太便宜就调到 4，曲线整体抬一档，不用改代码。

### 10.6 收敛速度与总花费（4 条词条，锁住的假定是 ~90% 百分位）

蒙特卡洛（目标 = 全部词条的**平均**百分位达到目标；累计金币按 §3 的 `1 + 0.6n` 逐次叠加；Lv.100 传说，首洗 2,538）：

| 锁几条 | 追到 80% | 追到 85% | 追到 90% |
|---|---|---|---|
| 0 | 59 次 / 135 万 | 185 次 / 1,310 万 | 898 次 / 3.2 亿 |
| 1 | 17 次 / 39 万 | 48 次 / 282 万 | 221 次 / 5,570 万 |
| 2 | 5.6 次 / 17 万 | 12.5 次 / 70 万 | 50 次 / 895 万 |
| 3 | 2.0 次 / 7 万 | 3.3 次 / 18 万 | 10 次 / 134 万 |

（金币是**中位数**：单次费用随次数线性涨、累计是二次的，平均值被少数长尾拉高得离谱，中位数更接近玩家体验。）

结论：所谓「锁得越多花的金币越多」是**单次**更贵；因为要摇的条数同步变少，**总花费反而可能更低**。这是设计意图——锁词条是拿金币买确定性，不是买更高的上限（上限见 §2.3，一点没动）。

### 10.7 平衡风险

- **天花板不变**：锁词条只是把「保留什么」变成玩家可选的，掷骰的池子与公式与掉落完全一致。
- **收敛快一个数量级**：终局玩家可以在一两百万金币内把两件装备推到 85~90% 词条质量，等效 DPS 约 +8~12%（§5.5 的估算仍成立）。这属于「金币换强度」，与用户定的「终局就是要难」不冲突：不花钱也能过，花钱只是更稳。
- **对「金币出口不封顶」是一点让步**：锁满 3 条后，每一档质量的价格是有限且可算的（90% ≈ 134 万）。先按 3 上线，若实测终局金币又开始堆积，把 `ReforgeLockFactor` 调到 4 即可。
- **探针已模拟洗练**（§5.4 已更新）：`SpendGoldOnReforge` 会在 BOSS 前把词条洗到 80%，锁住已达标的词条；因此 `EndgamePacing` 的 P200 数字从旧口径 113.7min 变为 117.2min 纯战斗 / 229.3min 含等待（洗练消耗随机数导致 RNG 流偏移，不代表洗练让游戏变慢）。

### 10.8 实现清单

1. `GameConfig.cs`：`ReforgeLockFactor` + `ReforgeCost(level, quality, reforgeCount, lockedAffixes)`（旧三参重载保留）；`GameConfigData.cs` 与 `game_config.json` 同步键。
2. `Models.cs`：`Equipment.AffixBit / PresentAffixMask / AffixValue / AffixText / LockedAffixCount / ReforgeCostWithLocks / ReforgeLockMultiplier`；`ReforgeResult` 加 `AllLocked`。
3. `LootSystem.cs`：`RollAffixes` 支持排除掩码；`ReforgeAffixes(e, lockedMask)` 只清空并重抽未锁的那几条。
4. `GameController.cs`：`ReforgeEquipment(slot, lockedMask = 0)`，费用走锁后的价格，日志带上锁数与倍率。
5. `GameUI.Panels.cs`：每张卡 5 行词条按钮（点击切换锁定）、费用行显示「锁 n 条 ×f」、按钮在满锁时显示「已全锁」；锁定状态是 `GameUI` 的临时字段，按 `Equipment` 引用判断是否换装清零。
