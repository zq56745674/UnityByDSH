# Unity AutoBattle 五槽期平衡调查（2026-10-21）：洗练定价、转生加速缺口、P1000 终局复测与 LateGameProbe 清理

工程 `HelloWorldProject/`（Unity 6000.6.5f1），workspace `E:\pytest\unitydsh1`。本文汇总 2026-10-21 一轮平衡调查的结论、实测数字与建议，供后续调参/复测时直接引用。相关文档：巅峰上限与 P0→P1000 旧口径 `1a09f494-5502-49e1-9ca6-08f74205bdc1`（两槽旧数据，本文的 P1000 复测替代它）；成就/转生落地验收 `884032e9-f795-4eea-ae52-4a84277dc555`；成就设计契约 `1066008a-f3e2-496e-8317-4c7895e2397d`。

## 0. 结论速览

1. **洗练（reforge）不整体提价**，只调 `ReforgeCostGrowth` 0.6 → 0.9（首洗价不变，压「同一件反复洗 + 锁词条」这条路径）。
2. **转生加速不足**（第 2 世 92.4%、满轮回 63.5%，目标 75~85% / 35~50%）：五条加成全在压练级段，而终局时间花在磨巅峰；建议先动 `RebirthExpPerRank` 与 `RebirthLegacyLevelPerRank`，不要先加战斗。
3. **P1000 终局节奏**五槽复测明显短于两槽旧口径：含等待 301.1 h（12.5 天），旧口径 333.2 h。
4. **LateGameProbe 清理**：删除 5 个仅服务旧评分口径切换的入口（338 行），1080 → 742 行，配置 149 键对 149 字段。
5. 以下参数改动**均未写入产品配置**（只在内存/探针里试算）；是否落地待用户拍板。

## 1. 洗练费用（用户问题 #5）

### 1.1 先纠正失效数据

README 与 `_balance/` 里「不洗练 11-10 要 88 次尝试 / 87 阵亡 → 洗练 80% 后 11 次 / 10 阵亡，只花 2,674 金」是 **2026-10-19 两槽口径**，五槽复测复现不出来。与 `docs/equipment-reforge.md §5.4` 同步更正：**2,674 金这个数字不要再引用**。

### 1.2 五槽复测（单关上限 30，seed 12345/777/2026/4242/8888/31337）

- 第 11 章中位尝试「开洗练 22 次 / 关洗练 21.5 次」，单种子差值 −6 ~ +22，整体落在种子噪声内：五槽之后 11-10 成败由掉落与磨层主导，词条质量不再是决定性变量。
- 单轮洗练花费 2,465~23,295 金；首洗 Lv.110 传说 2,762；而同档整轮金币收入约 2.3 万——洗练在新档已吃掉过半收入。

### 1.3 直接提 base 单价 = 把系统关掉（seed 12345 逐档实测）

| `ReforgeBaseCost` | 第 11 章尝试/阵亡 | 总阵亡 | 洗练花费 | 收尾金币 |
|---:|---:|---:|---:|---:|
| 200（现状） | 10 / 0 | 2 | 13,391 | 8,755 |
| 800 | 18 / 8 | 10 | 12,325 | 10,442 |
| 2,000 | 18 / 8 | 10 | 5,947 | 7,846 |
| 6,000 及以上 | 17 / 7 | 9 | **0** | 9,476 |

单价提到 ≥800 后新档一次也洗不起，效果等同关闭系统，因此提 base 不能起定价作用。

### 1.4 终局反复洗练的真实量级

把一套 Lv.110 传说从 ~50% 洗到 ~87%（探针 80% 线）四组实测：500,956 / 952,754 / 989,761 / 1,407,866，**平均 96.3 万**金。对照 P1000 全程只花 84.3 万、收尾剩 8.598 亿——洗练既不是终局瓶颈，也补不上金币软出口。

### 1.5 建议

- 只把 `ReforgeCostGrowth` 0.6 → 0.9（`GameConfig.cs:423`）：首洗 2,762 不变；第 11 次 17,818 → 27,620（×1.55）；31 次滚满约 86 万 → 约 130 万；端局把一套洗到 86% 平均 96.3 万 → 133.7 万（+39%，4 组实测）。
- **不动** `ReforgeLockFactor`（已是 3，锁两条 = 9× 单价，再高等于劝退锁词条）。
- 提价解决不了 8.598 亿金币软出口：终局收入亿级，任何单价乘 10 也只有百万级，属经济结构问题，按用户意见先保留。

## 2. 转生加速为什么只有 92.4% / 63.5%（用户问题 #2）

目标（`docs/rebirth.md:525-526`）：第 2 世回到 11-10 为 **75~85%**，满轮回 **35~50%**；50 种子实测 **92.4% / 63.5%**（加速不足）。

### 2.1 机制

五条转生加成的层级都在 `GameConfig.cs:681-699`：战斗 +1%/级、经验 +20%/级、金币 +20%/级、起始等级 +2/级、炼金药剂 +1 / 金币 +500。它们**全在压缩「练级段」**，而终局时间花在「磨巅峰」上。

seed 20261019 拆解（单种子）：

| | 第 1 世 | 第 2 世（G1/F1/A1） | 满轮回（全 5） |
|---|---:|---:|---:|
| 总时长 | 14.0 min | 14.1 min | 10.6 min |
| 第 1 章 | 3.6 min（13 次 / 3 阵亡） | 3.7 min | 1.5 min |
| 第 2~10 章 | 约 8.2 min | 约 9.6 min | 约 6.4 min |
| 第 11 章 | 2.2 min（30 次 / 20 阵亡） | 0.8 min（10 次 / 0 阵亡） | 2.7 min（37 次 / 27 阵亡） |

- 11-10 那一段确实被压扁（2.2 → 0.8 min），但它在总时长里占比小；第 1 章是裸装磨 1-1（起始 Lv.1 攻 10 防 5 血 100），经验/金币倍率完全无效，只有起始等级能救（+2/级只把第 1 章压到 3.7 min，+10 级才 1.5 min）。
- 终局反向膨胀：满轮回金币翻倍后探针洗练花掉 109,332（第 1 世 13,809），装备更早变强、更早撞 BOSS 磨层，11 章回到 2.7 min。

### 2.2 建议

先调 `RebirthExpPerRank` 0.20 → 0.35 左右、`RebirthLegacyLevelPerRank` 2 → 4，**不要先加战斗**——`RebirthBattlePerRank` +5% 已把无尽首死中位从 290 推到 315（约 +25 层，比设计预估的 +5~10 层强）。是否做 50 种子试算（参数只在内存、不写代码/config）待用户决定。

### 2.3 探针口径陷阱

必须**先选技能再套五条 rank**。先套 rank 会让三选一评分偏向被加成属性，构筑与正常玩家不可比；此前「满轮回无尽中位 125 层」是探针伪影（等于丢掉钢铁之躯），**不要引用**。`EndlessPacing.BuildFullPlayer` 与 `LateGameProbe.Build` 已改为技能挑选后套 rank。

## 3. P1000 终局节奏五槽复测（用户问题 #7）

`EndgamePacing`（seed 20261018，Lv.100 传说起、5 小怪 + 轮换 BOSS 循环、余钱全砸强化）：

- 首通 11-10 在第 14 次挑战 / P33 / 2.0 min。
- 累计 **119,842 次挑战**；纯战斗 **6,081.6 min（101.4 h）**；含 0.5s/只刷怪与 3s/BOSS 商店 **18,065.6 min = 301.1 h ≈ 12.5 天**（x4 档约 75 h）。
- 全程 24 阵亡；强化 486,240 + 洗练 842,890；收尾兜里 **859,843,626** 金币。
- 相对两槽旧数据（244 阵亡 / 7,781.8 min / 333.2 h）明显变短，尝试数几乎不变。

## 4. LateGameProbe 清理与 BGM 表述（用户问题 #16 / #17）

- 删除 5 个只为评分口径切换服务的入口：`ScoreAudit` / `ScoreRankAudit` / `ScoreBattleAudit` / `ScoreDummyAudit` / `ScoreWeightSearch`，共 338 行，1080 → 742 行；连带删除 8 个只被它们读取的 `ScoreWeight*` 配置项（GameConfig / GameConfigData / game_config.json 三处同步，149 键对 149 字段）。保留胜率/技能/生存/连携审计，`BalanceRegression.RunStaticOnly()` 返回 `PASS`。备份 `_archive/LateGameProbe.pre-cleanup.cs.bak`。
- BGM 表述改为「AI 生成、无第三方权利方、可随游戏分发」，去掉曲目作者前缀（README、`docs/audio-credits.md`）。
