# 平衡工具与基线

这个目录放在 Unity 工程外，免得被 AssetDatabase 当资源导入。

| 文件 | 内容 |
|---|---|
| `baseline.json` | 平衡回归基线：静态哨兵全文 + 新档过渡轨迹（`transition` 小节）+ 8 巅峰档 × 4 难度格胜率表（容差 0.5pp） |
| `shots/` | PlayMode 冒烟截图 |
| `README.md` | 本文件 |
| `balance-analysis.md` | 2026-10-18 全项目平衡分析：逐章通关率、满级后胜率曲线、经济与建议（数据来自本目录两个探针） |

## 探针与决策层的分工

- **`Assets/Editor/LateGameProbe.cs`** — 稳态探针。按 `p.level = chapter * 10` + 各抽一件该章精英品质装备造人，只测"这个阶段的玩家打不打得过"，不模拟从 Lv.1 一路成长的过程。
- **`Assets/Editor/NewGameProgression.cs`** — 过渡探针。从 `new PlayerData()`（Lv.1、空身、0 金币、0 药剂）起步，逐关先打小怪（血量继承）再打精英/关底，阵亡重试，直到通关或到达终局。回答的是"新玩家能不能玩下去"。
- **`Assets/Editor/EndgamePacing.cs`** — 终局节奏探针（2026-10-18 新增；2026-10-19 支持指定 targetParagon、同时报「纯战斗 / 含刷怪+商店」两种时间，并在每次 BOSS 前把词条洗到 80%）。从「Lv.100 + 传说装备 + 巅峰 0」起，在 11-10 反复「5 小怪 + 轮换 BOSS」，输出首次通关的巅峰/耗时、P1/P30/P50/P100/P150/P200/P300/…/P1000 的里程碑，末尾报「强化累计 / 洗练累计 / 两件装备的等级 / 兜里剩多少」。回答的是"满级要磨多久"；跑 P1000 用 `Run(20261018, 200000, false, 1000)`。
- **`Assets/Editor/EndlessPacing.cs`** — 无尽节奏探针（2026-10-19 新增；2026-10-25 D2 加 `fixedSkills` 第 13 参数与「技能槽」输出）。满装模板（Lv.100 巅峰 200、15 技能、传说 Lv.110 +15、词条质量 80%），默认 20 个固定种子逐层模拟，输出首死层数分布、层通关率、单层 P50/P90 与 50 层经济；可传 `paragonLevel` / `gearLevel` / `affixQuality` / `maxGear`，以及 `fixedSkills=true`（前面五个 rank 传 0）把技能槽固定为 1/2/4/9/14/13，避免技能三选一污染配装对比。当前 D2 口径（`EndlessBaseFactor=3.4`）用 `Run(50, 400, 20261019, 1000, 150, 0.85f, true)`：P1000 满倍率满词条首死中位 240（P10 227 / P90 250 / max 261），随机五槽 181（P10 161 / P90 195 / max 205，默认自动技能；固定技能会把防御抬高到 5,380、中位变 212）。回答的是"无尽能打多深、收益是否失控"。
- **`Assets/Editor/ProbePolicy.cs`** — 探针的玩家决策层（三选一挑卡、余钱砸强化、BOSS 前洗练），供上面几个探针共用。把候选技能真打三种 Lv.110 BOSS 打分，强化按「每金币换多少 `DPS + 有效生命/8`」排序，洗练用 `SpendGoldOnReforge` 把词条质量拉到 80%（锁住已达标的词条，不追 90%）；不吃 `p.currentHp`/`p.potionCount`/`p.gold` 的脏副作用（用 `finally` 还原）。

稳态探针天然看不到"起点不可玩"这类问题——它假定你已经站在终点。

过渡探针现在不只是"手动跑一下看看"，而是**常驻门禁**（2026-10-17 补，见下）：
```
NewGameProgression.Trace(seed, attempts)         → 每章一行：ch{章}|cleared|endLevel|attempts|deaths|seconds
NewGameProgression.CheckInvariants(SimResult)    → 与基线无关的硬约束，任何一次运行都必须过
BalanceRegression.RunStaticOnly()                → 静态哨兵 + 过渡轨迹比对（全量约 20ms 的模拟）
BalanceRegression.WriteTransitionBaseline()      → 只把 transition 小节写进现有基线，不动胜率
```
容差：`endLevel`/`level` ±2、`attempts`/`deaths` ±max(2/3, 30%)、`seconds` ±35%、`kills` ±20%；`stuck`/`cleared`/`chapter`/`stage` 必须完全一致。

## 跑法

```powershell
# 新档进度（约 10~20 秒，--timeout 单位是毫秒，默认 600 必须显式放大）
unity command --format json eval -- --code 'return AutoBattle.EditorTools.NewGameProgression.Run(12345, 30, true);' --timeout 300000

# 一行判定（PASS/FAIL，含硬约束：不卡死、每章末等级、终局等级、阵亡上限）
unity command --format json eval -- --code 'return AutoBattle.EditorTools.NewGameProgression.RunAssert(12345, 30);' --timeout 300000

# 过渡轨迹（入库格式）
unity command --format json eval -- --code 'return string.Join("\n", AutoBattle.EditorTools.NewGameProgression.Trace(12345, 30));' --timeout 300000

# 平衡回归
unity command --format json eval -- --code 'return AutoBattle.EditorTools.BalanceRegression.RunStaticOnly();' --timeout 300000
unity command --format json eval -- --code 'return AutoBattle.EditorTools.BalanceRegression.Run(false);' --timeout 300000

# 无尽节奏（20 个种子，约 30 秒）
unity command --format json eval -- --code 'return AutoBattle.EditorTools.EndlessPacing.Run();' --timeout 300000
```

## 2026-10-17 的修复与数据

### 问题

新档 1-1 必死，且无自救路径。1-1 的怪是 Lv.10（`Stages.cs` 里 `monsterLevel = 10 * chapter`，第 1 章整章 Lv.10），而主角是 Lv.1 空身：一只要打 42 击 ≈ 56 秒，自己 5.4 秒就被揍死；阵亡既不给经验也不给金币，还清空本关进度，复活后刷的是满血新怪 → 无限死亡循环。无装备能打死 Lv.10 普通怪的最低等级是 8，打掉关底精英要 12。

### 三处改动

1. **内容曲线**（`Stages.cs` / `GameConfig.ChapterOfMonsterLevel`）— 第 c 章改为 Lv.10(c−1)+1 ~ 10c，1-1 是 Lv.1，11-10 是 Lv.110。`LateGameProbe` 仍用 `10 * chapter` 造怪，等于章末档，`baseline.json` 语义不变（回归实测 PASS）。
2. **经验补偿**（`GameConfig.ChapterExpFactor`）— 怪物经验乘 `1 + (lv−1) × 0.07`（Lv.110 约 8.6 倍）。原因是升级成本二次、怪物经验线性，只改内容曲线时主角只到 Lv.66，满级/巅峰/技能卡全不可达。
3. **阵亡保底**（`GameController.HandlePlayerDied`）— 阵亡时按"已打掉的血量比例"给该怪经验，仍保留"本关进度作废"的惩罚。每次最多一只怪的全额经验，送死不是最优解。

|---|---|
| 改之前 | 卡死 1-1，3 次重试全灭，0 击杀 |
| D1 之后 | 1-1 → 11-9 全通、0 阵亡；章末等级 10/17/23/29/35/40/46/51/56/61；卡 11-10（Lv.68，30 次全灭） |
| D2 之后 | 章末等级 11/21/32/43/53/64/76/88/100/100/100；仍卡 11-10（Lv.100 + 巅峰 93，549 击杀） |

### 2026-10-17（补）过渡验证进门禁

问题不在数值，而在验证方法：两套工具都在"稳态假设"里打转——关卡表只记怪级，胜率表直接把玩家放在第 c 章、等级 10c、装备白送。那次新档死锁（Lv.1 打 Lv.10、复活无收益）**两套工具全绿**，因为没有任何一处真的从 Lv.1 走到第 2 章。

现在这条过渡是常驻哨兵，任何让成长曲线断档的改动都会立刻报红。实测：把 `ChapterExpScalePerLevel` 临时改回 0（等价于撤销经验补偿），

- `RunAssert` → FAIL 8 条：卡在 11-10（Lv.69），且第 4~10 章末等级全部低于下一章怪级下限；
- `RunStaticOnly` → FAIL 20 处，`[过渡]` 逐项列出 `ch3 endLevel: 32 → 23`、`ch4 seconds: 63 → 141` 这种漂移。

2026-10-17 当时的基线（seed 12345）：ch1~ch10 每章 10 次尝试 0 阵亡，章末等级 11/21/32/43/53/64/76/88/100/100；ch11 36 次尝试 26 阵亡；收尾 `end|stuck=0|level=100|paragon=102|kills=545|deaths=26`。当前带洗练基线见 `_balance/baseline.json` 的 transition 小节（ch11 20/10）。

### 尚未覆盖

三个入口（稳态探针、过渡轨迹、胜率表）原本都不模拟技能三选一、手动换装、装备强化，也不模拟玩家操作失误。2026-10-18 补了 `ProbePolicy` 之后，三选一与强化已经由它接管；2026-10-19 起洗练也接管（每次 BOSS 前洗到 80%）。仍然不模拟的是**手动换装**（只走自动换装）与操作失误。第 11 章的阵亡是"AI 只靠部分经验硬顶"的结果，真人会更早回头刷装备。改数值后建议两个探针都跑 + 开一局新档看到第 2 章。无尽探针同样复用 `ProbePolicy`（含洗练）。

### 2026-10-18 平衡改造（六条设计指令）

按用户指令落地的六件事：

1. **终局 BOSS 保持难**：不削 `MaxTier*`；但实测「传说装 + 巅峰 26」平均 7 次挑战就能打过，终局只硬一分钟，于是补了一层 `FinalBossStatFactor = 1.6`（只作用于关底 BOSS，不碰 11-1~11-9 的精英）。2026-10-23 复测定格 1.6：把倍率抬到 1.8 / 2.2 / 3.0 / 5.0 只能把首通推到 P44 / P50 / P50~71 / P75~90，却让 30 种子新档 11-10 通关率从 25/30 掉到 17 / 16 / 9 / 3 —— 同一件 BOSS 是两条路共用的门，故「推到巅峰 100 之后」的目标作废（见 `balance-analysis.md` §3.5.4a）。
2. **巅峰经验超线性**：`2000 + 200p + 20p²`（先按 12 落地，探针补了决策层后偏快，又抬到 20，见下节）；P0→P200 累计 5,731 万经验，纯战斗 1.9 小时、含刷怪+商店 3.8 小时。
3. **阵亡不返经验**：`HandlePlayerDied` 删掉按血量折算的部分经验；死了就回本关刷小怪（每轮 5 只照常给经验），再回来打关底。
4. **技能槽保持 6 个**：不改 `SkillSlotsPerKind`，`LateGameProbe.Build` 也改成「只填空槽、槽满不替换」，和游戏内 `TryAutoEquip` 一致（之前模拟会替换，导致 P100→P150 胜率非单调）。
5. **终局 BOSS 轮换**：11-10 的 BOSS 类型按挑战次数 `attempt % 3` 轮换（近战→远程→暴击怪），不再掷骰；其它关底仍是随机类型。
6. **1~10 章压迫**：`ChapterPressure = 1 + 5.5%×(章-1)`（2026-10-23 由 4% 上调），章末 BOSS 再乘 `1 + 4%×(章-1)`（由 3% 上调）；第 11 章不吃（它有自己的 ×3 终局档）。上调理由与 300 套抽样复测见 balance-analysis.md §3.5.2a。另外**精英战前不再回满血**（`HealBeforeFight=false`），一关变成连续的消耗链。

### 2026-10-18 装备洗练 + 锁词条上线（2026-10-19 起探针也模拟洗练）

设计文档在 `docs/equipment-reforge.md`，实现走 `GameController.ReforgeEquipment` → `LootSystem.ReforgeAffixes`。

- 洗练重抽**全部**副词条、条数不变，抽样与掉落共用 `RollAffixes(e, level, count)`，因此**天花板完全不变**：洗练只是把「等一件好词条」的方差用金币买掉，不会抬高任何一条词条的上限，也不改变终局 BOSS 的强度标定。
- 费用 `(200 + 14×(Lv−1)) × 品质系数 × (1 + 0.9×已洗次数)`（递增系数 2026-10-21 由 0.6 提到 0.9，见 docs/equipment-reforge.md §5.6）：Lv.100 传说 2,538 起，第 1/2/3 次 2,538 / 4,821 / 7,105；一件洗 20 次约 48.5 万、洗满 31 次约 124 万（Lv.110 传说）。
- **探针已接入洗练（2026-10-19）**：`ProbePolicy.SpendGoldOnReforge` 留够药钱后，每次 BOSS 前挑词条质量更低的一件洗，锁住已达到 80% 的词条，不追 90%；`NewGameProgression` / `EndgamePacing` / `EndlessPacing` 都已调用。新档 A/B（seed 12345）：不洗练 11-10 要 88 次尝试 / 87 阵亡 / P60；洗到 80% 只要 11 次 / 10 阵亡 / P44，洗练只花 2,674 金（以上为两槽口径）。**2026-10-21 五槽复测没有复现这个差距**：6 个种子（12345 / 777 / 2026 / 4242 / 8888 / 31337，单关上限 30）第 11 章中位尝试「开洗练 22 次 / 关洗练 21.5 次」，落在种子噪声内；单轮洗练花费 2,465~23,295 金，已接近整轮金币收入（约 2.3 万）的上限。结论改为「新档洗练并不便宜、终局也吃不满金币」，详见 docs/equipment-reforge.md §5.4–5.5。**2026-10-21 已按该建议落地**：`ReforgeCostGrowth` 0.6 → 0.9（首洗价不变，第 11 次 17,818 → 27,616，端局一套洗到 86% 96.3 万 → 133.7 万）。**2026-10-22 已按 0.9 重跑 P1000**（seed 20261018）：强化 324,240 + 洗练 708,389（0.6 口径为 486,240 + 842,890）、收尾兜里 859,284,167（0.6 口径 859,843,626）、终局五件 90%/80%/90%/88%/88% 质量。单价抬高后探针少洗了几次，`Random` 流分叉，因此终点数值与里程碑都只作新基线，不与 0.6 口径逐项对照。
- 静态哨兵不受影响：洗练常量不参与公式采样，`RunStaticOnly()` 仍然 `PASS`。
- **锁词条（同日追加，§10）**：在洗练面板上点词条行即可锁住，锁住的种类与数值都不重抽，费用按 `3^锁条数` 加价（实测 Lv.100 传说第 4 次 ×3 = 21,316、第 5 次 ×27 = 274,061）。锁 k 条把待抽从 4 条压到 4−k，追 80% 词条质量的中位次数 58 → 17 → 5.6 → 2.0，累计金币中位 135 万 → 39 → 17 → 7 万：单价指数上涨、总花费反而下降。**分布一字未改，所以天花板与终局 BOSS 标定都不动**——它买的是确定性，不是保底。
- 金币的「软出口」问题没有根本解决：P200 满级兜里约 560 万（2026-10-22 五槽 P1000 实收 8.593 亿），锁定能把「等好词条」的方差买掉，但锁完之后钱照样堆着。要真正解决得靠保底/抬高单条上限（会抬天花板，需重估终局）或另开出口（成就 / 转生 / 强化上限）。
- 锁词条不单独建模：`SpendGoldOnReforge` 会锁住已达到目标质量的词条，费用按实际锁数计算；静态哨兵不采样这些常量，`RunStaticOnly()` 仍 `PASS`。

已知的张力：满装（传说）的自动玩家在 1-10 章仍然 0 阵亡——装备品质把战力拉到 2 倍以上，章节压迫只能让「装备没那么好」的玩家感到压力；要让满装玩家也翻车，需要把怪物再抬到 ~2.5 倍，那会把稀有装备的玩家直接钉死。这一层留给后续（要么压缩品质倍率，要么给满装玩家单独的难度档）。

**同日晚些时候的第二轮（探针决策层 + 巅峰曲线二次校准）**：这一版的终局节奏是先按 `q=12` 量的（2026-10-18 旧口径，探针尚未模拟洗练），满级 136.6 / 110.3 min。但把 `EndgamePacing` 的选卡从「永远 candidates[0]」换成 `ProbePolicy`（每个候选真打三种 BOSS 打分）、并让它把余钱砸进强化之后，同样两个种子只用了 **76.3 / 77.3 min** —— 差额不是数值变了，是旧探针把玩家想得太笨：6 张随机技能 + 两件 +0 传说装。为了守住「满级大约两小时」，把 `ParagonExpQuadratic` 从 12 抬到 20（总需求 3,620 万 → 5,731 万经验），重跑得到 108.0 / 113.7 min，技能 15/15、两件 +15。

三组数字是三种口径，不是互相矛盾：136.6 / 110.3 min = 旧探针（不选卡、不强化）+ q=12；76.3 / 77.3 min = 决策层探针 + q=12；108.0 / 113.7 min = 决策层探针 + q=20。以后动技能表、强化费用或怪物属性，三个探针要一起重跑——只看其中一份就会得出相反结论。
