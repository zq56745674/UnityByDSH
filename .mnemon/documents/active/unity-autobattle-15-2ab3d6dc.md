# Unity AutoBattle 技能强度审计（15 技能边际贡献）

用户诉求：分析当前各技能强度。以下为一次完整的量化审计结论，供后续调数值时参考。相关但不同主题的既有记录：装备评分口径 `4f6621d0-f8c4-4dab-81fb-719d78ddf259`、属性收益/阈值复评 `ab8f6186-b189-4fa8-9d4b-5708a9bde932`。

## 1. 审计方法与口径（可复用）

实现落在 `HelloWorldProject/Assets/Editor/LateGameProbe.cs`（本次新增 `SkillAudit` / `SurvivalAudit` / `ComboAudit`，另有既有的 `ScoreAudit:142` / `ScoreRankAudit` / `ScoreBattleAudit` / `ScoreDummyAudit` / `ScoreWeightSearch:413`）。共享基线构造 `Build(int paragon):113`（Lv.100 传说武器+衣服、按 `paragon / GameConfig.ParagonPassiveEvery` 授予随机技能并填充同 kind 槽位、`FillHp`）。

三套独立口径，互为交叉验证：

- **输出口径**：`SkillAudit(paragon, seconds, runs, winGames)`，主角每帧回满血（只看输出、不看死活），对 Lv.110 Boss，木桩伤害由 `DummyDamage:383` 以 0.05s 步进累计（怪物被打死后重建）。基准：Lv.100 传说套 + 巅峰 25（技能 Lv.3，数值 ×1.20），无技能基准木桩 DPS 3354（300s × 10 次）。
- **生存口径**：`SurvivalAudit(paragon, monsterLevel, runs)`，摘掉武器把输出压到接近 0，只测能撑几秒。基准属性：生命 8702 / 防御 786 / 攻击 355。
- **组合口径**：`ComboAudit` 做主动技能两两组合与触发技能两两组合，看第 2 个技能的**边际**相对它单装时衰减多少（公共冷却挤压）。

**口径踩坑记录**：初版用 60s × 5 次、胜率 200 场，出现两个问题——胜率列全 0%（单技能打不过 Lv.110 Boss，无区分度），且 ±3% 属木桩噪声。改为 300s × 10 次、胜率 40 场后才可用。`Fight:499` 的战斗口径含自动喝药（与游戏内一致）。

## 3. 生存口径：有效区间断裂

对 Lv.110 Boss、无武器主角：无技能基准存活 **3.0 秒**。

| 技能 | 存活 | 提升 |
|---|---|---|
| 护盾生成 | 3.4s | +11.0% |
| 不死之身 | 3.2s | +5.8% |
| 钢铁之躯 | 3.1s | +2.9% |
| 吸血鬼 | 3.1s | +1.7% |
| 其余全部 | 3.0s | ≈0 |

对手降到 **Lv.105 或 Lv.95**：基准直接变 **2000 秒（超时不死，主角带药水回血快于挨打）**，所有技能 0.0% 区分度。结论：**生存属性几乎没有有效区间**——Lv.110 是 3 秒猝死，Lv.105 以下是不死，中间没有过渡带。

## 4. 关键发现

1. **公共冷却不是瓶颈（与初始预期相反）**。主动技能两两组合，第二个技能的边际几乎等于它单装收益，挤压损失仅 **-0.1 ~ +1.1pt**：重击+狂暴 总 24.5% / 第 2 个边际 17.7%（单装 17.1%）；狂暴+斩杀 22.8% / 4.8%（5.0%）；重击+旋风斩 10.2% / 4.1%（3.1%）。原因：CD 8~30 秒、公共 CD 仅 1 秒，撞不上。**两个主动可以放心一起带。**
2. **触发技能只有反击可用**。反击 +28% 的机制是怪物攻击频率（Lv.110 Boss 每 0.2~0.3s 一次）远高于主角出手（0.27s），而反击**没有内置冷却**，等于把怪物攻速按 50%×84% 折算成主角额外 DPS。暴击连锁仅 +2.4%，受限于暴击率本身 17%、触发次数少。
3. **巨人杀手是唯一「无脑必带」**：对精英/Boss +24% 乘算且无条件，实测 +23.3% 与理论吻合。
4. **致命打击被自身收益递减吃掉**：暴伤 +36% 只值 +5.3%，因为基准暴伤已 335%，`1+c×(d-1)` 中 d 越大加 d 边际越小。同理斩杀 CD 20s 且仅 <30% 血生效，720% 常打在残血上溢出。
5. **护盾生成是唯一「生存真的有用」的技能**（+11%），但绝对量太小：18% 最大生命的一次性护盾在 3 秒猝死局里只换 0.4 秒。

## 5. 建议调整方向（尚未执行）

| 问题 | 建议 |
|---|---|
| 反击过强（+28%，无冷却） | 加 0.5~1 秒内置冷却，或概率降到 30% |
| 旋风斩过弱（+3.9%） | 3×96% → 3×150%，或 CD 12s → 8s |
| 斩杀过弱（+6.7%） | 阈值 30% → 50%，或倍率 720% → 1000% |
| 致命打击边际差 | 改成乘算（暴伤 ×1.2）而非加算 +36% |
| 生存技能全废 | 提高数值，或把 Lv.110 Boss 的 ×3 攻击强化拆成「攻击 ×2 + 生命 ×1.5」，给防御/护盾留有效区间 |
| 濒死爆发、不死之身 | 触发阈值（15%/20%）在 3 秒猝死局里根本来不及触发 |

审计末尾已向用户提出「按此方向调一版数值，还是先挑几条」，**用户尚未选择，不要自行改数值**。

## 6. 操作备注

- 调审计脚本后需 `AssetDatabase.Refresh(ForceUpdate)` 再 eval；写入 `LateGameProbe.cs` 时出现过一次 `Error: ReplaceFileW EIO (Win32 1175)`，重试同一写入即成功（Windows 占用导致的瞬时写失败，非脚本错误）。
- 探针在 Editor play 模式经 `eval` 调用，例如 `return AutoBattle.EditorTools.LateGameProbe.SkillAudit(25, 300f, 10, 40);`。
- 本工程 `editor_play` 无 `run_in_background` 参数，需自行设置并恢复 `runInBackground`（本次收尾恢复为 `false`）。
